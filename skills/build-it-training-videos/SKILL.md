# Build IT Training Videos

## Establish the brief

- Read the supplied script, guide, or workflow first. Treat the approved source as authoritative for wording and steps. Preserve approved terminology, required notices, and the intended outcome. Flag missing or conflicting details that would change what the learner sees or does.
- Identify the audience, one action the learner should perform, and the visible result that confirms success. Capture the app, platform, and version or tenant conditions where they change the steps. Ask one focused question at a time only when an unresolved choice affects the deliverable.
- Default to a 45–60 second, 16:9 clip for internal channels. Use the requested duration, aspect ratio, and delivery channel when supplied. For narrated formats, write in plain language and allow time for the learner to see each action and result.
- Inventory approved assets. Use authorized, sanitized screenshots or screen recordings and fictional practice data. Keep credentials, personal information, and protected health information out of the script, capture, examples, and export. Use labeled placeholders for missing assets and flag the shots that need them.
- Choose the production path based on the request. Use Camtasia for a straightforward screen-capture demo or a storyboard handoff. Use Remotion for recurring series with editable motion graphics or a requested code-based render. Reuse the existing project and approved brand assets where available.

## Present the storyboard for approval

Use the following sequence. Omit a beat when the learner can complete the task without it.

| Video type | Suggested sequence |
| --- | --- |
| M365 or Copilot tip | Job task → action or prompt → visible result → how to verify it |
| Software walkthrough | Starting screen → steps in order → confirmation → repeat the task |
| New-hire IT explainer | When to use the process → where to go → what to provide → what happens next |
| Post-training refresher | Trigger for the task → one key step → what a correct result looks like |

Provide the objective, source, runtime, format, production path, and any asset or verification gaps. Use a timestamped table with one row per scene and columns for time, narration, on-screen action and text, and asset or edit cue. Identify the most important on-screen moment and hold it long enough to read. Use motion, zoom, and highlights to direct attention without covering the control, captions, or presenter.

For a storyboard-only request, deliver the review-ready storyboard. Before recording, writing production code, or rendering, obtain approval of the storyboard unless the user has already approved the same scene plan and authorized production. After approval, apply timestamped feedback to the targeted scenes and review adjacent cuts and captions for timing changes.

## Produce the approved video

- **Camtasia.** Deliver a timed edit plan, narration, capture list, callouts, and caption guidance. Edit or export when requested and when the project, media, and tooling are available. Label any handoff items that still require recording or export.
- **Remotion.** Check the available project, rendering tools, assets, and output settings before implementing. Use the existing animated explainer or Remotion workflow when available. Render a representative five-second segment first and check the fit, pacing, and caption placement before rendering the full video. Provide the MP4, editable project source, and captions when supported. Include a contact sheet and short revision log when producing iterative full renders. If the tooling cannot export a video, provide the completed handoff or source and identify the blocked export.

## Verify the result

Use pass, needs fix, or unverified for the relevant checks. Record the evidence and fix any failed checks within scope before final delivery.

- Compare the steps, labels, and outcome against the approved source and available app evidence. Mark live app or tenant behavior unverified if it could not be tested.
- Confirm that each scene supports the learner action and that the video shows what success looks like.
- Review the whole clip at the intended playback size. Check readable text, contrast, safe placement, and enough time to read prompts and results.
- Check captions against narration, including app terminology. Verify captions, callouts, and narration that conveys essential on-screen actions.
- For an MP4, confirm it plays and matches the requested duration and dimensions. Check the audio and captions in playback. Deliver the versioned files and summarize any remaining verification gaps.

## Example

Turn an approved OneDrive file-sharing guide into a 60-second Camtasia storyboard. Use a fictional practice file. Show the sharing steps in the guide, then hold on the permissions view so employees can confirm who has access. Flag any tenant-specific options that still need verification and present the storyboard for approval.
