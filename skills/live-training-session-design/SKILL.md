# Live Training Session Design

## Purpose

Turn a confirmed learning need into a timed, accessible session with practice, evaluation, and reinforcement.

Primary audience: Workplace.

## When to use it

Use for a workshop, demonstration, webinar, or live virtual, in-person, or hybrid session after confirming the learning need.

## Inputs and requirements

Confirmed performance outcome; audience; duration; modality; source material; delivery constraints.

A supported skill host; access to supplied text/files. No bundled scripts or external services.

## Workflow guide

1. Confirm the performance outcome, audience baseline, group size, delivery mode, duration, source material, accessibility needs, and facilitator constraints. If training need is unconfirmed, identify that dependency rather than claiming training will solve the problem.
2. Write observable objectives linked to a task and evidence of success. Flag missing performance criteria instead of inventing organizational standards.
3. Build an agenda around relevance, concise explanation/demonstration, guided practice, independent application, feedback, and transfer. Choose the number of sections to fit the task; do not force a fixed agenda or practice percentage.
4. Create a run of show with start/end time, purpose, facilitator action, participant action, materials, and evidence. Count transitions and breaks inside the available time. Recalculate the total; if required activities do not fit, expose the trade-off.
5. Specify practice inputs, directions, expected result, feedback method, and a source-supported answer or rubric. Include accessible participation alternatives that assess the same objective. Distinguish a worked example from an actual learner result.
6. Prepare facilitator prompts, transitions, materials list, technology setup, and a fallback for failed access or connectivity. Do not invent interface labels, clicks, or product features. Mark unverified steps for confirmation.
7. Match evaluation to the objectives; separate satisfaction from demonstrated learning. Identify follow-up practice, support, owner, timing, and maintenance trigger, labeling proposed values.
8. Return the session profile, objectives, run of show, practice and scoring guidance, facilitator notes, materials, contingencies, evaluation/reinforcement plan, and unresolved gaps. Check objective/practice/evidence alignment and timing. Producing a plan does not mean slides, workbooks, or delivery have been completed.

Expected outputs: Objectives, run of show, practice plan, facilitator guidance, materials, contingencies, evaluation, and reinforcement.

```txt

Ask one focused question at a time only if a material input is missing.
```

## Customize before running

- `[performance_goal]`: Observable workplace task Example: Find the correct help article and submit a complete request.
- `[audience]`: Roles, experience, group size, access needs Example: 12 new support coordinators.
- `[minutes]`: Total available session time Example: 60 including transitions.
- `[sources]`: Approved content to teach Example: A supplied help-center procedure.
- `[delivery_constraints]`: Mode, tools, access, staffing Example: Virtual; one facilitator; no breakout rooms.

## Example use and output

Fictional input: A 60-minute virtual session for 12 coordinators using a supplied help-request procedure, without breakout rooms.

| Time | Purpose | Learner evidence |
| --- | --- | --- |
| 0–5 | Relevance and baseline question | Name the information needed for a request. |
| 5–15 | Demonstrate a complete request | Identify required fields in the supplied procedure. |
| 15–30 | Guided practice | Complete a fictional request with support. |
| 30–45 | Independent scenario | Submit a practice response against the checklist. |
| 45–55 | Feedback and correction | Correct missing fields and explain the change. |
| 55–60 | Transfer and close | Choose a next-use opportunity and support resource. |

Total: 60 minutes. Fallback: use an accessible text scenario if the practice system is unavailable. Follow-up: repeat one practice task after initial job use; owner and date require confirmation.

## Check before using

Times total the available duration; objectives have matching practice/evidence; sources support task steps; another facilitator can follow the plan; accessible and technology fallback paths exist.
