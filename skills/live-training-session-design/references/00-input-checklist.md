# Input checklist

## Minimum required inputs

| Input | Why it matters | If missing |
|---|---|---|
| Topic | Establishes scope | Ask only if the request is not identifiable |
| Learner or business need | Prevents feature dumping | State a provisional need and label it |
| Audience | Controls language, examples, pacing, and prerequisites | Ask if materially uncertain |
| Observable post-training performance | Drives objectives and assessment | Ask before building substantive content |
| Delivery format | Changes interaction and logistics | Ask when not inferable |
| Duration and breaks | Controls scope and pacing | Ask before finalizing an agenda |
| Source materials | Establishes authority and traceability | Inventory what is available |
| Constraints and review needs | Controls risk and release status | Flag unknowns |

## Useful optional inputs

- Expected enrollment
- Learner access and permissions
- Instructor experience
- Available applications or room technology
- Existing LMS fields
- Required templates
- Desired practice model
- Knowledge or performance baseline
- Accessibility needs
- Evaluation approach
- Follow-up resources
- Required reviewers

## Proportional alignment rule

Ask a question only if the answer would change one or more of the following:

- Learning objectives
- Course scope
- Timing
- Delivery method
- Activity design
- Assessment design
- Source authority
- Risk controls
- Output format

Otherwise, proceed with a labeled assumption.
