# Failure recovery and backup rules

## Failure record
For every material failure point, define:
- Failure signal
- Likely cause
- Immediate action
- Maximum recovery effort
- Alternate live path
- Offline backup
- Presenter language
- Continue, switch, skip, or stop rule

## Decision rules
- Continue when recovery is immediate and does not confuse the learning point.
- Switch when a verified alternate path preserves the takeaway.
- Skip when the scene is optional and time or stability is threatened.
- Stop when privacy, security, safety, data integrity, or misleading behavior is at risk.

## Backup hierarchy
1. Alternate live workflow
2. Prepared completed state
3. Annotated screenshots
4. Short prerecorded clip
5. Static storyboard or paper simulation

## Presenter recovery language
Use calm, factual language. Name the learning point, not the technical embarrassment. Example: “The live environment is not returning the expected state, so I’m switching to the prepared result. The decision and next step remain the same.”


Read [state and retry rules](10-state-recovery-and-equivalence.md). A missing success signal is an uncertain outcome, not permission to repeat a mutation. Inspect state first; do not retry unknown create/assign/send outcomes. Distinguish planned assets from created and actually verified backups.
