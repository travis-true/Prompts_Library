# Accessibility checklist

## Course content

- Use a logical heading structure.
- Use plain language appropriate to the audience.
- Define specialized terms.
- Keep instructions short and sequential.
- Do not rely on color, position, sound, or gestures alone.
- Provide descriptive link text.
- Provide useful alt text for meaningful visuals.
- Use live text instead of images of text when possible.
- Ensure examples and scenarios are inclusive and necessary to the task.

## Live delivery

- State instructions aloud and provide them in text.
- Describe meaningful on-screen actions.
- Allow processing and response time.
- Provide an alternative to verbal participation.
- Provide an alternative to precise mouse, drag, or handwriting tasks when practical.
- Avoid requiring cameras unless justified.
- Explain how learners can request help.
- Plan keyboard-accessible alternatives for interactive tools.

## Materials

- Use readable font sizes in file-ready layouts.
- Maintain sufficient contrast.
- Use real headings and accessible tables.
- Identify table headers.
- Avoid merged cells when they impair navigation.
- Caption prerecorded media and plan captions for live virtual delivery.
- Check reading order in exported documents and slides.

## Assessment

- Assess the objective, not an unrelated access barrier.
- Provide equivalent ways to respond when the response mode is not part of the objective.
- State success criteria before the activity.
- Allow assistive technology and reasonable accommodations.

## Reporting

Record accessibility checks as Pass, Needs revision, or Not checked. A generic statement such as “make accessible” is not evidence.

## Separate design from execution
Report accessibility-design and accessibility-rendered separately. Check actual files for contrast, size, heading structure, reading order, table headers and meaningful visual alternatives as applicable. Record actual caption and keyboard tests for the selected delivery tools. Label standards or thresholds as project targets unless a controlling requirement establishes them; verify current official requirements when a named standard is mandatory. A Markdown checklist is not proof that a future DOCX, slide deck or PDF is accessible.
