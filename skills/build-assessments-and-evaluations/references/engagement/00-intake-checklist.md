# Intake checklist

| Input | Why it matters | If missing |
|---|---|---|
| Course, outline, or objectives | Establishes scope | Ask if no learning context can be inferred |
| Audience and baseline | Controls difficulty and scenarios | Use labeled assumption only when low risk |
| Observable performance | Defines evidence | Create provisional performance and flag it |
| Delivery format | Controls methods and tools | Provide format-neutral primary and fallback |
| Duration and placement | Controls cognitive load and timing | Provide relative placement rather than clock time |
| Existing assets | Supports preserve and improve | Treat as none if confirmed absent |
| Assessment stakes | Controls rigor | Clarify consequential signals first; otherwise label any practice-only assumption |
| Technology | Controls implementation | Use tool-neutral design and fallback |
| Accessibility needs | Controls alternatives | Apply accessibility-by-design defaults |
| Sources and standards | Controls authority | Label recommendations and review needs |
| Evaluation expectations | Controls follow-up plan | Select only levels needed for the stated decision |

Ask only when the answer would materially change the resulting design.

## Consequence override
The low-stakes default applies only when no consequential-use signals are present and the assumption is explicitly labeled. Unknown certification, authorization, eligibility, job qualification or employment effects require clarification and an unresolved-stakes record. Ask about intended decisions before generating consequential scoring.
