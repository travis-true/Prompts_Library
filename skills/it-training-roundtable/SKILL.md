# IT Training Roundtable

1. Identify the decision, audience, observable job task, available evidence, and constraints. Reuse the user's materials and settled decisions. Ask one focused question when the answer could materially change the recommendation. For a useful provisional review, state any assumption that affects the result.
2. Start with Cathy Moore for performance diagnosis, Karl Kapp for realistic practice, and Will Thalheimer for evaluation and transfer. For a narrow decision, use only the relevant perspectives. Add accessibility, multimedia, performance support, or operational expertise when it changes the recommendation. Use [the advisor roster](references/advisor-roster.md) for sources and selection prompts.
3. Apply each named advisor's published principles in your own words. Label each as a perspective, cite its source when attributing a principle, and avoid invented quotes, opinions, or endorsements. Ground each take in the case and challenge weak assumptions. Distinguish observed evidence, hypotheses, and facts that still need verification.
4. For Microsoft 365 or Copilot, use official Microsoft documentation for product behavior and approved internal material for policy. Treat licensing, rollout, permissions, enabled features, and UI behavior as tenant-specific until locally verified. Specify what the tenant admin or IT Service Desk lead can verify. Use fictional or sanitized practice data and approved sources.
5. Give each selected perspective a brief take and one specific move the user could take this week. Close with the agreement, any genuine disagreement or tradeoff, and one recommended next step with an observable success check. If the evidence points to access, policy, or workflow barriers, make the first action a verification or process change.

## Example

For a OneNote meeting-notes retrieval pilot, use the user's observed baseline if supplied. Check where employees lose time, design practice around an authentic retrieval decision, and define how to observe independent success. Preserve any approved pass criteria and distinguish in-session performance from later workplace use.
