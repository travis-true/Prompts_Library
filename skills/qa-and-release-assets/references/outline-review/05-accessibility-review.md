# Accessibility review by scope

## Accessibility-design
Inspect the outline for written instructions, processing time, nonverbal and individual response alternatives, assistive technology, equivalent assessments, no camera requirement without reason, no dependence on color/sound/position alone, and meaningful descriptions. Cite actual design provisions or their absence. Assess required alternatives against scope and impact.

## Rendered-material accessibility
Inspect actual slides, handouts, documents, images or media for readable type, contrast, heading structure, table headers, live text, reading order and useful alternatives as applicable. Record tests actually performed. If artifacts do not exist or were not opened, use Not checked; design statements are not execution evidence.

## Delivery environment
Check the selected platform, captions, keyboard access, assistive technology routes, sharing and response mechanisms when delivery is reviewed. Unselected or untested tools remain Not checked. Give separate designed fallback and actual tested fallback status.

## Evidence and reporting
For each domain record scope, artifact/version, applicability, method, observed evidence, gaps and next owner. Do not collapse these domains into one Pass. Cite a verified defect only when observed; missing design support can be a design finding without proving the future delivery inaccessible. Standards or thresholds must come from controlling project requirements or be labeled recommendations; verify current official standards when a named standard is required.
